SOURCE PROJECT · BUILD INSTRUCTIONS

Ubuntu-based Desktop OS

A general-purpose desktop and laptop system using Ubuntu 24.04 LTS, GNOME, and the existing Ubuntu installer. “Desktop OS” is a working name.

Not an installer or a published OS. This deliverable is a source recipe and build setup. No custom image has been generated, booted, or installed.

What is included

  • Everyday application package list: LibreOffice, VLC, text editor, calculator, system monitor.
  • Wallpaper, desktop defaults, and a local getting-started guide.
  • Base image download tooling with signed-checksum and pinned-image validation.
  • A guarded customization script for Cubic’s virtual terminal.
  • Test-report template and gated local release-candidate staging.

Source location: os/ubuntu-desktop/. Existing web apps are unchanged.

1. Check the source

From the project folder, run python3 scripts/check-project.py, then python3 -m unittest discover -s tests -v.

These are source checks, not operating-system boot or installation tests.

2. Prepare an Ubuntu build computer

Use a separate Ubuntu desktop computer with admin access, internet, about 40 GB free storage, and preferably 8 GB RAM or more. Follow the official Cubic installation instructions. Review its third-party PPA before installation.

Copy the source folder there. Run python3 scripts/fetch-base.py --metadata-only, then python3 scripts/fetch-base.py. The second command downloads the multi-GB Ubuntu image.

3. Customize and generate an ISO

  1. Open Cubic and import the verified official desktop ISO.
  2. Keep the installer, browser snap seeds, stock kernel, and boot configuration.
  3. Copy the complete source folder to /tmp/ubuntu-desktop inside Cubic’s virtual terminal.
  4. Run bash scripts/apply-in-cubic.sh --apply-in-cubic from that folder. Never run it on a normal host.
  5. Save the recorded package inventory, then remove only the copied temporary source folder from the target image.
  6. Continue Cubic’s wizard to generate the development ISO.

The detailed instructions are in docs/BUILD.md. ISO assembly is interactive; there is no unattended image build in this setup.

4. Test the actual image

Start with a disposable UEFI VM and an empty virtual disk. Test live boot, installation, reboot without the ISO, everyday apps, networking, display/audio, and updates. Then test selected physical computers.

Record specific evidence in a copy of config/test-report.template.json, including the exact ISO checksum. Do not mark unrun tests as passed.

5. Prepare a release

Use scripts/prepare-release.py with the custom ISO, completed test report, and a new output folder. It refuses incomplete reports, mismatched image hashes, and overwrites.

It stages a local candidate only. Complete licensing and security review, sign release checksums, and upload the image to a suitable download host before publishing a download page.

Important limits

  • This is an independent Ubuntu customization, not an official Canonical product.
  • Windows and macOS apps do not automatically work.
  • Support is limited to tested hardware; Secure Boot, offline installation, encryption, and suspend/resume need separate tests.
  • The working source files need a distribution license before public source release.
  • A website’s Publish action does not create or test a bootable OS.
